# Cloudflare Email API

A small, authenticated HTTP API for sending email from a Cloudflare Worker using [Cloudflare Email Service](https://developers.cloudflare.com/email-service/). It can also forward inbound mail through Email Routing.

- **Production:** https://email-api.msar.me
- **workers.dev:** https://email-api.msar.workers.dev

Opening the root URL shows interactive API docs.

## Endpoints

| Method | Path      | Auth         | Description                         |
| ------ | --------- | ------------ | ----------------------------------- |
| `GET`  | `/`       | —            | API documentation page              |
| `GET`  | `/health` | —            | Liveness check                      |
| `POST` | `/send`   | Bearer token | Send a plain text and/or HTML email |

Inbound mail is handled by the Worker's `email` handler (see [Inbound forwarding](#inbound-forwarding)).

## Project structure

```
src/
├── index.ts            # Worker entry: routes fetch + email events
├── handlers/
│   ├── send.ts         # POST /send
│   └── inbound.ts      # Email Routing forwarder
├── auth.ts             # Constant-time bearer token check
├── validation.ts       # Request body validation
├── http.ts             # JSON / HTML / CORS response helpers
├── docs.html           # Documentation page served at /
└── env.d.ts            # Optional env vars not inferred by wrangler
wrangler.jsonc          # Worker config: bindings, routes, observability
```

`worker-configuration.d.ts` is generated by `wrangler types` (it runs on install) and is not committed.

## Requirements

- Node.js 20+
- Yarn 1 (or npm)
- A Cloudflare account with a domain onboarded to **Email Service** (for sending) and, optionally, **Email Routing** (for inbound)

## Setup

### 1. Install

```bash
yarn install
yarn wrangler login
```

### 2. Configure Cloudflare

In `wrangler.jsonc`:

- **`send_email[].allowed_sender_addresses`**: the verified addresses the Worker may send from. `FROM_EMAIL` must be one of them.
- **`routes`**: the custom domain the Worker is served on. Change `email-api.msar.me` to your own hostname, or remove the block to use workers.dev only.
- **`observability`**: Workers Logs is on, so `console.log`/`console.error` output shows up in the dashboard.

After editing `wrangler.jsonc`, run `yarn cf-typegen` to regenerate types.

### 3. Secrets and variables

| Name         | Required | Description                                       |
| ------------ | -------- | ------------------------------------------------- |
| `API_KEY`    | yes      | Bearer token clients must send to `/send`         |
| `FROM_EMAIL` | yes      | Sender address (must be an allowed sender)        |
| `FROM_NAME`  | yes      | Sender display name                               |
| `FORWARD_TO` | no       | Verified Email Routing destination for inbound mail |

**Local development:** copy the example file and fill it in. Never commit `.dev.vars`.

```bash
cp .dev.vars.example .dev.vars
```

**Production:** set each value as a Wrangler secret.

```bash
yarn wrangler secret put API_KEY
yarn wrangler secret put FROM_EMAIL
yarn wrangler secret put FROM_NAME
yarn wrangler secret put FORWARD_TO   # optional
```

The required names are declared under `secrets.required` in `wrangler.jsonc`, so `wrangler dev` warns when one is missing. If `API_KEY` or `FROM_EMAIL` is missing at runtime, `/send` returns `500 Service is not configured` instead of accepting requests.

To generate a strong key:

```bash
openssl rand -base64 32
```

### 4. Develop

```bash
yarn dev
```

The `EMAIL` binding is `remote: true`, so local requests to `/send` send real email through your Cloudflare account.

### 5. Verify and deploy

```bash
yarn verify   # wrangler types + tsc + wrangler deploy --dry-run
yarn deploy
```

### Deploying from Git (Workers Builds)

To deploy on every push, connect the repository under **Workers & Pages → your Worker → Settings → Builds**:

- **Build command:** `yarn verify`
- **Deploy command:** `npx wrangler deploy`

Secrets are kept on the Worker, so set them once with `wrangler secret put` (or in the dashboard). Lockfiles are git-ignored in this repo; commit `yarn.lock` if you want reproducible CI installs.

## Usage

### Health check

```bash
curl https://email-api.msar.me/health
```

```json
{ "success": true, "status": "ok" }
```

### Send an email

```bash
curl -X POST "https://email-api.msar.me/send" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "to": "recipient@example.com",
    "subject": "Hello from Cloudflare",
    "text": "Plain text fallback",
    "html": "<h1>Hello</h1><p>Sent from my Worker.</p>",
    "replyTo": "hello@msar.me"
  }'
```

| Field     | Type   | Required    | Notes                          |
| --------- | ------ | ----------- | ------------------------------ |
| `to`      | string | yes         | Recipient address              |
| `subject` | string | yes         | Up to 998 characters           |
| `text`    | string | conditional | Required if `html` is omitted  |
| `html`    | string | conditional | Required if `text` is omitted  |
| `replyTo` | string | no          | Must be a valid address        |

Bodies are limited to 1,000,000 characters each.

**Success:**

```json
{
  "success": true,
  "message": "Email sent successfully",
  "messageId": "..."
}
```

### Errors

Every error has the form `{ "success": false, "error": "...", "code"?: "..." }`.

| Status | When                                                                    |
| ------ | ----------------------------------------------------------------------- |
| `400`  | Invalid JSON, or Email Service rejected the message (`code` included)   |
| `401`  | Missing or wrong bearer token                                           |
| `404`  | Unknown path                                                            |
| `405`  | Wrong method for the path (an `Allow` header is set)                    |
| `415`  | `Content-Type` is not `application/json`                                |
| `422`  | Validation failed, e.g. `"A valid to email address is required"`        |
| `429`  | Email Service rate or daily limit reached                               |
| `500`  | Worker not configured, or an unexpected send failure                    |

## Inbound forwarding

With Email Routing enabled on the domain, add a routing rule (or the catch-all) that sends mail to this Worker. The `email` handler then:

- rejects mail sent to `noreply@…` addresses
- rejects everything if `FORWARD_TO` is not set
- otherwise forwards the message to `FORWARD_TO` and adds an `X-Original-Recipient` header

`FORWARD_TO` must be a verified destination address in Email Routing.

## Security

- The sender is fixed server-side. Requests can't set a `from` field.
- `/send` requires a bearer token, which is compared in constant time.
- CORS is open (`*`) so the docs page and tools can call the API. The API key must still stay server-side: never ship it in browser or mobile code.
- Call this API only from trusted backends.
